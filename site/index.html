Features
PDF or one HTML file+

A PDF, portrait or landscape, or one HTML file that shows the window a group to a screen.

Any editor theme+

deck’s own themes, or any theme of an editor you have installed.

Comments included+

What you and the agent said goes with it. Leave it out, and the file and its .deck carry none.

deck pack (.deck)+

The deck as one .deck file, with its code. Paths become repo-relative, and a secret stops the pack.

Attach to a PR+

The HTML file carries the .deck inside, so whoever you send it to can open it in deck and answer.

Works offline+

The fonts are embedded and there is no script. It reads the same on a plane.

A miss used to go straight to the database. Now the first request on each server loads it, and the rest wait on that one promise. The cache is filled once, and every waiter gets the same user.

Next: the one line, and the first deck. ↓

deck is one line away.

One script downloads deck for your machine, checks the download is intact, and puts it on your PATH. Then deck setup asks a few questions.

in a terminal

$curl -fsSL https://raw.githubusercontent.com/henit-chobisa/deck/main/install | sh

Run it as yourself, not with sudo.·Usage counts are sent only if you say yes. See what is sent.
Rather read it first? Read the script, or download the tarball and its checksum from Releases.

Then, the first deck

  1. 1
    deck setup asks a few questions.

    How deck should look; it can borrow your editor's theme. And whether to give each agent it finds a short skill, so it knows when to reach for deck.

  2. 2
    Ask your agent about some code.

    A bug, a plan, or a review. The skill tells it to show you in a deck, not summarise in chat.

  3. 3
    A bar appears at the bottom of your screen.

    That's your first deck. Open it when you're ready. The agent can't open it for you.
